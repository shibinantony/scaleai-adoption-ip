# Gateway, evaluations and runtime evidence

The platform director owns a common gateway for model traffic. Security Engineering owns deny decisions. The workflow owner owns the acceptance sample and the manual queue. The invoice-exception pilot should be able to answer three questions from client-owned records. Who submitted this draft, which policy and model permitted it, and what did the reviewer decide?

## Immediate priority · Day 0–90

**Handoff.** Deliver a private gateway route, a fixed synthetic evaluation suite, an evidence collector and a tested switch to manual review. Use separate service identities for runtime inference, evaluation and policy publication. Only the private gateway identity may reach inference.

| Control and accountable owner | Implementation and evidence | Acceptance threshold | Blast radius if omitted |
|---|---|---|---|
| **TOOL-01 · Authenticate and contain spend.** Gateway owner | Derive tenant and workload from validated identity. Apply per-tenant rate limits, prompt redaction and token ceilings before inference. Reserve the maximum billable units atomically across replicas. Reconcile with actual use and hold an uncertain reservation after a timeout. Store rule version and reservation ID. | All missing or mismatched identity fixtures are denied before inference. Under concurrent requests at the remaining limit, the sum of authorized reservations never exceeds the configured cap. An exhausted budget returns a controlled denial. | One tenant can consume shared capacity, incur uncapped cost or send sensitive fields into a downstream component. |
| **TOOL-02 · Stop unsafe outputs before delivery.** Application security lead | Implement NeMo Guardrails flows that call local deterministic checks for required fields, allowed actions and source membership. Buffer the complete draft. Route failed checks and rail timeouts to the manual queue with a reason code. Enforce tool permissions again at the server. | All invalid-schema, invalid-citation, prohibited-action and unavailable-rail fixtures deliver zero draft bytes to the user. The same fixture and rule version produce the same allow or deny decision. | Streaming or a failed check can expose a partial draft or present an unauthorized action. |
| **TOOL-03 · Qualify releases on replayable examples.** Assurance lead | Run fixed, approved synthetic transcripts through PyRIT scoring and use Giskard for retrieval and answer checks. Keep fixtures, scorers, any judge, model endpoints and reports in the client boundary. An independent reviewer reconciles label disputes. Attach suite counts, case IDs, fixture and build hashes to the release. | The versioned release checklist passes, including its coverage minima for severe toxicity, unsupported claims and defensive scenarios. Missing evidence, skipped cases or a scorer error blocks promotion. Record each suite separately. | An apparent improvement can arise from dropping a class of failures or changing the judge. |

NeMo supports programmable flows and actions. Use local functions for the mandatory checks. A model-based objection can refer a case for review, while deterministic authorization still governs access and release. [NeMo Guardrails developer guide](https://docs.nvidia.com/nemo/guardrails/about-nemo-guardrails-library/overview)

For an evaluation of an outdated policy, supply two synthetic versions with different effective dates, an expected citation and the acceptable manual disposition. Score the exact source version and reviewer judgment separately. Record both the expected and observed result. Giskard documents retrieval and groundedness checks, and PyRIT supplies scoring components. [Giskard RAG evaluation](https://docs.giskard.ai/oss/checks/use-cases/rag-evaluation) · [Microsoft PyRIT](https://microsoft.github.io/PyRIT/)

### Trace one workflow through the pilot

Issue an opaque trace ID at ingress. The gateway records a tenant pseudonym, workflow, allow or deny result, policy digest and route. Inference adds model digest, latency and token counts. Keep case revision and reviewer disposition in the access-controlled business record, joined by trace ID. Send only the gateway policy's allowlisted attributes through a private OpenTelemetry collector into a client-owned security information and event management (SIEM) system. Restrict the identity crosswalk to authorized incident personnel. Drop prompt bodies, document chunks, tool arguments, raw supplier IDs, authorization headers and exception text before export. OpenTelemetry describes field removal and redaction in the collector. [OpenTelemetry guidance on sensitive data](https://opentelemetry.io/docs/security/handling-sensitive-data/)

The security operations lead owns the trace acceptance check. Replay a synthetic approval, denial and timeout, then retrieve all three decisions by trace ID within five minutes. Scan the runtime, collector and SIEM outputs for seeded sensitive markers and require zero matches. A missing denial event conceals an authorization failure. A leaked marker makes the logging stack a second sensitive-data store. Store the trace reconciliation and marker-scan result with the pilot evidence.

## Ongoing priority · Day 90+

**Handoff.** Supply an approved cache eligibility list, a tenant-level alert with an on-call owner and a tested promotion record for each model or policy change.

| Control and accountable owner | Implementation and evidence | Scale pass condition | Blast radius if omitted |
|---|---|---|---|
| **TOOL-04 · Constrain semantic cache reuse.** Knowledge owner | Keep caching off for invoices, personal content, mutable balances, approvals and tool results. For approved static policy FAQs, use tenant-specific cache partitions and bind keys to entitlements, locale, effective policy version, model and prompt. Re-authorize every hit, enforce expiry, and invalidate on source or ACL change. | Every denied or ineligible fixture results in zero hits. Revocation immediately prevents reuse. Before enabling a similarity threshold, review at least 200 near-neighbor pairs per enabled language with zero materially wrong matches. | A similar question can receive a stale answer or a response written for a different access group. |
| **TOOL-05 · Detect loss of evidence.** Security operations lead | Reconcile ingress counters against unique terminal decision events after the delivery grace period. Deduplicate at-least-once terminal decision events by opaque trace ID. Treat conflicting terminal decisions for one trace as a reconciliation failure. Use an encrypted local spool with a capacity alarm and stop automated release if the mandatory audit record cannot be durably written. | Every admitted request has one reconciled terminal decision within five minutes in an outage drill. The first failed durable write holds the affected decision. The on-call lead receives a gap alert within five minutes. | A collector outage can leave a run of approved drafts with no attributable decision record. |
| **TOOL-06 · Make regressions block rollout.** Release manager | Compare candidate and current bundles against the frozen suite in a private runner. Bind signed results to model, rules, code, dataset and scorer digests. Canary an approved candidate in one tenant before expanding. | A deliberately incomplete scorecard and a report with a different candidate digest both prevent promotion in the deployment adapter. A failed canary closes the route and restores the prior approved bundle or manual review within 15 minutes. | Stale evidence can authorize a different build across every tenant on the route. |

Review budget denials, cache eligibility, abstentions, unsupported drafts and latency jointly. A high cache hit rate has value only if reviewer acceptance and source validity hold. Implement the gateway and deployment adapters in the client's environment and exercise them with the same fixture set used for release.
